# النموذج اللغوي المحلي المجاني

## الاستخدام دون حساب خارجي

أصبح الوضع الافتراضي `AI_MODE=browser`. تستخدم صفحة الصيانة نموذج **Qwen3‑0.6B**
داخل المتصفح بواسطة Transformers.js وWebAssembly، دون مفتاح API أو حساب لدى
OpenAI أو Groq أو Hugging Face، ودون رسوم استدلال من مزوّد سحابي.

1. افتح `/local-model` أو زر «تجربة النموذج المجاني دون تسجيل دخول» في صفحة الدخول.
2. اختر مثالًا اصطناعيًا واضغط «تشغيل النموذج مجانًا».
3. يظهر تقدم التحميل، ثم فئة العطل التي يقترحها النموذج. لا تمثل التجربة تقييمًا طبيًا.
4. للاستخدام داخل النظام، ادخل بحساب التطبيق المعتاد وافتح صفحة الصيانة. خيار النموذج
   المحلي مفعّل افتراضيًا. اختر الجهاز واكتب وصفًا فنيًا ثم اضغط «التحقق والتحليل».
5. يمكن إلغاء انتظار النموذج ومتابعة القواعد والمراجع فورًا. يؤدي تعطيل الخيار إلى
   استخدام القواعد فقط، ويظهر مصدر النتيجة بوضوح.

لا يتطلب هذا الحل تثبيت Ollama أو إعداد خادم للنموذج. حساب نظام الصيانة ما زال مطلوبًا
للوصول إلى الأجهزة والسجلات؛ صفحة تجربة النموذج عامة ولا تكشف بيانات النظام.

## المتطلبات وحدود المجانية

- تنزيل أولي يقارب **950 ميغابايت**: أوزان النموذج وحدها 919,096,585 بايت، إضافة إلى
  محلل الرموز وملفات التشغيل. تُنزّل الأوزان العامة من Hugging Face، ويستضيف الموقع
  ملفات WASM من النسخة المثبتة للمكتبة. لا يُنزّل النموذج أثناء بناء الموقع.
- يستفيد التشغيل اللاحق من ذاكرة التخزين المؤقت عندما يسمح المتصفح بها. قد يحذف
  المتصفح الملفات عند نقص المساحة أو استخدام التصفح الخاص؛ ليست هناك ضمانة للتخزين الدائم.
- متصفح حديث يدعم WebAssembly وWeb Workers وHTTPS، وذاكرة متاحة لتحميل الأوزان
  ومصفوفات الاستدلال. يفضّل البدء بحاسوب؛ الأجهزة محدودة الذاكرة قد تفشل أو تبطؤ.
- لا يحتاج التشغيل إلى WebGPU أو بطاقة رسومية خاصة أو عزل عبر COOP/COEP؛ يستخدم خيط
  WASM واحدًا داخل Worker حتى تبقى الواجهة قابلة للتفاعل.
- لا توجد رسوم API، لكن التنزيل يستهلك بيانات الإنترنت والتشغيل يستهلك موارد الجهاز.
  لا يمكن ضمان زمن ثابت أو تشغيل كل جهاز. موقع الصيانة وخادمه ما زالا يحتاجان اتصالًا؛
  هذا ليس تطبيقًا كاملًا يعمل دون إنترنت.

## الدور الفعلي للنموذج

النموذج مصنّف مساعد لوصف العطل، وليس مولّدًا لتعليمات الصيانة. يختار رمزًا واحدًا من:

| الرمز | الفئة |
|---|---|
| A | POWER — الطاقة والبطارية |
| B | SENSOR — الحساسات والقياس |
| C | CIRCUIT — الدارات الكهربائية |
| D | MECHANICAL — الميكانيك والتسريب |
| E | SOFTWARE — البرمجيات والعرض |
| F | ALARM — إنذار دون سبب محدد |
| G | OTHER — عطل فني آخر |
| H | UNKNOWN — وصف غير واضح أو ليس بلاغ عطل |

تُستخدم تعليمات نظام وأمثلة قصيرة ثابتة، ثم وصف البلاغ. يسمح فك الترميز المقيد بإنتاج
رمز فئة واحد فقط. تُحسب احتمالاته بواسطة النموذج الحقيقي، ولا تستبدلها مطابقة كلمات
مفتاحية. التقييد يمنع إخراج نص حر، **ولا يضمن صحة اختيار الفئة**. لا تُعرض احتمالات
الرموز على أنها ثقة طبية أو نسبة دقة.

لم يُجرَ تدريب أو ضبط دقيق أو استرجاع متجهي. النموذج صغير وعام الغرض، وقد يخطئ في
العربية أو الإنجليزية وفي المصطلحات الفنية. يتطلب تقييمه بيانات مستقلة موسومة من مختصين.

## مسار التنفيذ والتحقق

1. تبدأ صفحة الصيانة الاستدلال عند طلب المستخدم فقط. تثبّت المدخلات أثناء التشغيل.
2. يحمل Worker النموذج المثبت ويقرأ الوصف. لا يدخل الرقم التسلسلي أو موقع الجهاز
   أو هوية المستخدم إلى تعليمات النموذج. يُرفض تجاوز 1024 رمز إدخال شامل التعليمات
   والأمثلة؛ لا يُقتطع آخر البلاغ لأن ذلك قد يخفي معلومات مهمة.
3. تعيد الواجهة رمز الفئة وإصدار الأوزان وزمن التنفيذ وبصمة سياق الطلب إلى
   `POST /api/intelligent-support/analyze-fault` في الحقل `browser_llm`.
4. يتحقق الخادم من تسجيل الدخول والجهاز وبنية النتيجة، ويربط بصمة النص ونوع الجهاز
   وحالة اتصال المريض بالطلب الحالي. بيانات الجهاز المرجعية تؤخذ من قاعدة البيانات.
5. يظل تقدير الخطورة والأولوية والطوارئ من قواعد الخادم والمراجع. لا يستطيع رمز الفئة
   خفض طوارئ أو خطورة المرجع. تُقترح مراجعة الهندسة الطبية للفئات الفنية، ويُطلب التوضيح
   للفئة UNKNOWN، مع بقاء الإحالة السريرية أولوية عندما تحدد القواعد طوارئ.
6. تبقى إجراءات الإصلاح والمصادر من قاعدة المراجع. لا يُملأ أي حقل لإصلاح الجهاز
   بنص يولّده النموذج. كل نتيجة تحتاج مراجعة المختص ولا تُسند مهمة تلقائيًا.
7. يظهر المصدر `BROWSER_LLM_CATEGORY_WITH_RULE_GUARDS` عند قبول فئة فنية محلية،
   أو `REVIEW_REQUIRED` عند الامتناع، أو `RULES` عند التعطل/الإلغاء/التعطيل.
8. مهلة التحميل 15 دقيقة مع زر إلغاء دائم، ومهلة الاستدلال دقيقتان. ينهي الإلغاء أو
   التعطل Worker، وتبدأ المحاولة التالية بتشغيل جديد. لا توجد إعادة طلب تلقائية.

**حد الثقة:** النتيجة المحلية `client_reported=true`. يمكن لعميل معدّل تزوير رمز الفئة
وبصمة المدخل؛ التحقق يكتشف عدم تطابق الطلبات العرضي، ولا يثبت أن النموذج نفذ فعلًا.
هوية النموذج وبصمة إعداداته في السجل تمثل الإعداد المتوقع، وليست شهادة تنفيذ من الخادم.
تُسجل فئة العميل منفصلة عن `decision` الخاصة بالمزوّد السحابي؛ لا تُنسب خطورة القواعد
إلى النموذج. لا يجوز استخدام السجل وحده لإثبات نتائج تجريبية للرسالة الجامعية.

## الخصوصية

لا يرسل التشغيل المحلي وصف البلاغ إلى مزوّد استدلال. يستقبل Hugging Face طلبات تنزيل
ملفات عامة وقد يرى بيانات الاتصال المعتادة، لا نص البلاغ ضمن هذه الطلبات. في صفحة
الصيانة يُرسل البلاغ إلى خادم التطبيق لحفظ التحليل والمراجعة، كما في المسار السابق.
صفحة التجربة تستخدم أمثلة ثابتة فقط ولا ترسلها إلى API التطبيق. يجب أن تخلو الأوصاف
من بيانات المرضى أصلًا؛ تنقيح الخادم تقريبي ولا يضمن إخفاء الهوية.

## إعادة الإنتاج والفحص

- النموذج الأصلي: `Qwen/Qwen3-0.6B`، ترخيص Apache‑2.0.
- تحويل ONNX العام: `onnx-community/Qwen3-0.6B-ONNX`.
- الإصدار المثبت: `da1453100cf3ff33ef56d17983fc7a8648706db6`.
- الضغط: `q4`، ملف `onnx/model_q4.onnx`.
- SHA‑256 للأوزان: `d43d836fc5e240df9013733ccd214972c5d21bd9ec47e574e4f1e359cf90aed0`.
- المكتبة: `@huggingface/transformers@3.8.1`؛ تعتمد نسخة ONNX Runtime المقفلة في lockfile.
- قالب الإدخال: `enable_thinking=false`؛ توليد جشع لرمز واحد مقيد بـ A–H.
- الإعدادات والأمثلة: `frontend/src/llm/localModelConfig.json`، ونسخة مطابقة في الخادم
  يفحصها اختبار آلي. تسجل بصمة SHA‑256 للإعداد الكامل.

من مجلد `frontend`:

```bash
npm ci
npm test -- --run
npm run build
npm run smoke:llm
```

الأمر الأخير اختبار **استدلال حقيقي على CPU في Node**، منفصل عن اختبارات الوحدة؛
ينزّل أوزانًا عامة ولا يستخدم API مدفوعًا. يمكن ضبط `LOCAL_MODEL_PATH` لنسخة محلية
مطابقة للبصمة. يلزم اختبار `/local-model` أيضًا للتحقق من WASM والمتصفح والتحميل.
CI المعتاد لا ينزّل الأوزان؛ لا يمثل نجاح اختبارات المحاكاة وحده نجاح استدلال حي.

في اختبار CPU تمهيدي بستة أوصاف اصطناعية أثناء التطوير، طابقت نسخة q4 الفئة المتوقعة
في أمثلة البطارية العربية والبرمجيات الإنجليزية وفشل إمداد الأكسجين والنص العربي غير
الفني؛ أخطأت في مثال حساس الحرارة ولم تحدد مثال مفصلة الغلاف. استُخدمت أمثلة مرتبطة
بالتوجيه أثناء التطوير، لذلك **هذه ملاحظات تشغيل وليست عينة تقييم مستقلة أو نسبة دقة**.
تتضمن تجربة التشغيل المنشورة ثلاثة أمثلة بسيطة، ولا تثبت التعميم أو السلامة السريرية.

## الإعدادات السحابية السابقة

تظل تكاملات OpenAI وGroq متاحة لاستدعاءات API التي لا تحمل `browser_llm`، بعد إعداد
`AI_MODE=openai` مع `OPENAI_API_KEY`، أو `AI_MODE=groq` مع `GROQ_API_KEY` على الخادم.
هذه خيارات متقدمة منفصلة تتطلب حسابًا وشروطًا وحصصًا لدى المزوّد، ولا يحتاجها الحل الجديد.
`AI_MODE=reference` أو الاسم القديم `demo` يشغل القواعد لاستدعاء API دون نتيجة متصفح.
الافتراضي في الإعدادات وRender وDocker هو `browser`؛ غياب نتيجة المتصفح في هذا الوضع
يعطي `browser_result_required` مع نتيجة القواعد، وليس نجاح نموذج وهميًا.

ترسل الواجهة الجديدة `browser_llm` حتى عند التعطيل أو الفشل. **لا تتحول إلى مزوّد سحابي**
حتى إذا بقي مفتاح قديم في بيئة الخادم. لا تخزن المفاتيح في الواجهة أو Git.
مسار `/api/fault-reports/analyze` القديم يبقى مرجعيًا؛ دمج النموذج يخص صفحة الصيانة.
