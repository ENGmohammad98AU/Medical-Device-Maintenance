# دورة البلاغ والتحقق من الحل

يربط هذا الإصدار البلاغ النصي بسجل تحليل واحد ودورة متابعة قابلة للتدقيق: استقبال البلاغ، تصنيف الفئة بواسطة النموذج عند نجاحه، اختيار مرجع مناسب، مراجعة المختص، توثيق الإجراء المنفذ، تسجيل نتيجة التحقق ثم الإغلاق أو المتابعة. تعمل صفحتا الصيانة وتقارير الأعطال عبر المسار نفسه.

## الضوابط الوظيفية

- لا يمكن الإغلاق من واجهة التحديث العامة أو المسار القديم دون تحقق موثّق. نجاح الحل يتطلب قرار APPROVED أو MODIFIED، وإجراءً منفذًا ونتيجة تحقق غير فارغين، طول كل منهما بين 3 و4000 محرف بعد إزالة المسافات الطرفية.
- تقبل حقول وصف البلاغ ورسالة الخطأ حتى 4000 محرف، مع رفض الرسالة الفارغة والقيم الصريحة null في حقول التحديث الإلزامية. الحد النصي في نموذج الإدخال لا يلغي حد الرموز المستقل للنموذج؛ عند تجاوزه يظهر فشل صريح للمسار اللغوي.
- تغيير نص البلاغ أو الجهاز يلغي صلاحية الموافقة السابقة. إعادة التحليل تعيد البلاغ إلى IN_PROGRESS وتطلب مراجعة جديدة.
- إعادة فتح البلاغ المغلق تتطلب سببًا. تصبح الدورة NEEDS_ANALYSIS ولا يمكن إغلاقها باستخدام الموافقة القديمة. تُحفظ نسخة الدورة السابقة، بما فيها الإجراء ونتيجة التحقق، ضمن resolution_events في سجل تدقيق التحليل السابق.
- يحتفظ التحليل بمعرّف البلاغ بعد الإنشاء لمنع إنشاء نسخة أخرى عند الحفظ أو إعادة المحاولة. تتوقف أزرار الحفظ وتعديل المدخلات أثناء المعالجة.
- يبقى تنفيذ إجراءات صيانة الأجهزة والتحقق من نتائجها من مسؤولية المختص. النموذج لا ينفذ إصلاحًا ماديًا ولا يثبت نجاحه تلقائيًا.

## اختيار النموذج وإعادة الإنتاج

النسخة المعدة للنشر تستخدم `onnx-community/Qwen3-0.6B-ONNX`، الإصدار المثبت `da1453100cf3ff33ef56d17983fc7a8648706db6`، بضغط q4 داخل WASM في المتصفح، دون مفتاح API أو حساب مزوّد. يحتفظ المصنف بتوجيهه المثبت المتوافق مع النسخة الخفيفة، مع توجيه منفصل لاختيار المرجع. لم يُعتمد نقل توجيه نسخة 1.7B مباشرة إلى 0.6B لأنه أخفق في مثال البطارية العربي ضمن اختبار WASM. تُطابق إعدادات الواجهة والخادم لضمان تسجيل الإصدار الصحيح.

اختُبرت نسخة Qwen3-1.7B في مرحلة التطوير وحققت 32 إجابة صحيحة من 40 على تشغيل CPU أصلي، لكن تحميلها في اختبار WASM توقف بسبب نفاد ذاكرة بيئة الاختبار ذات حد 8 GiB. لذلك لا تُنسب نتيجة 80% إلى النسخة الخفيفة المنشورة، ولا يُعد نجاح الاختبار الأصلي دليلًا على صلاحية نموذج أكبر للمتصفح.

تتضمن المستودعات اختبارات دورة البلاغ وحالات مرجعية اصطناعية. تُشغّل من مجلد backend باستخدام `python -m pytest -q` ومن frontend باستخدام `npm test -- --run` و`npm run build`. اختبارات الاستدلال الحقيقي التي تنزّل الأوزان: `npm run smoke:llm:support` و`npm run smoke:llm:wasm`. ينفّذ `npm run benchmark:llm` تقييمًا من 40 حالة ويطبع Accuracy وMacro-F1 ومصفوفة الالتباس وإعدادات النموذج وزمن التنفيذ.

مجموعة الحالات الأربعين مجموعة تطوير جرى الاطلاع على أخطائها أثناء تعديل التوجيه؛ ليست مجموعة تحقق مستقلة. لا تعني نسبة اكتمال الوظائف أو نسبة التطابق التقديرية مع عنوان الرسالة دقة تصنيف مماثلة. يتطلب إثبات دقة قابلة للتعميم عينة جديدة موسومة من مختصين لم تُستخدم في تطوير التوجيه.
