# ترقية النموذج المحلي إلى Qwen3‑1.7B

تستخدم هذه النسخة Qwen3‑1.7B بصيغة GGUF وضغط Q4_K_M عبر wllama 2.4.0 داخل المتصفح. لا تحتاج إلى حساب مزود أو مفتاح API، ولا ترسل نص البلاغ إلى مزود النموذج. يبقى حفظ البلاغ وتحليل الخطورة والتحقق من المراجع على خادم النظام.

## سبب تغيير محرك التشغيل

بلغ حجم ملف ONNX الأصلي q4 نحو 2.15 غيغابايت، وتعذر تحميله في اختبار WASM ضمن حد ذاكرة 8 GiB. تجاوزت صيغة q8 الذاكرة أيضًا، بما فيها تجربة تعطيل prepacking. حملت q4f16 لكنها أخفقت عند الاستدلال. لذلك انتقل التنفيذ إلى GGUF بحجم 1,107,409,472 بايت، مع إبقاء توجيه التصنيف v2 والفئات والأمثلة نفسها. تغيير الضغط والمحرك يمنع إسناد نتيجة ONNX السابقة إلى هذه النسخة دون إعادة قياس.

يُستخدم قالب Qwen3 النصي مع تعطيل التفكير المطول. يُقيّم النموذج النص ثم يُقيد اختيار الرمز بفئات التصنيف الثماني أو بالمراجع المعروضة فعلًا. لا يؤلف نص إصلاح حرًا؛ نص الإجراء مرجعي ويخضع لمراجعة المختص. تُعاد الاستفادة من بادئة السياق المشتركة، ويزيل المحرك لاحقة الطلب السابق عند اختلاف الطلب.

## التشغيل

افتح `/local-model` واضغط «تشغيل النموذج مجانًا». يُنزل المتصفح نحو 1.1 غيغابايت أول مرة، وقد يحتفظ بالأوزان في التخزين المحلي. استخدم Chrome أو Edge حديثًا؛ يفحص النظام دعم Memory64 قبل تنزيل الأوزان. سرعة التنفيذ تعتمد على الجهاز، وقد يستغرق تجهيز السياق وقتًا ملحوظًا. تبقى إمكانية الإلغاء والمتابعة بالقواعد متاحة مع إظهار مصدر النتيجة.

سبب مشكلة التخزين هو حصة OPFS المحدودة في بعض ملفات المتصفح، رغم وجود مساحة على الجهاز. يفحص النظام الحصة، ويستخدم الأوزان المحفوظة إن كانت كاملة. إذا لم تكفِ الحصة أو تعذر الوصول للتخزين، ينزل الملف للتشغيل المؤقت مباشرة دون حفظه في مخزن النموذج الدائم. يعالج أيضًا تجاوز الحصة أثناء التنزيل، ويحذف فقط ملف النموذج غير المكتمل المرتبط بهذا التنزيل. لا يحذف البلاغات ولا بقية بيانات الموقع. قد يلزم إعادة التنزيل بعد إغلاق الصفحة؛ يبقى توفر الذاكرة والاتصال شرطًا. يحاكي اختبار CI حصة 128 MiB للتحقق من هذا المسار.

يضيف عامل خدمة من أصل الموقع نفسه ترويستي COOP وCOEP لتفعيل الذاكرة المشتركة والتشغيل المتوازي. قد تُحدّث الصفحة نفسها مرة واحدة قبل إظهار النماذج؛ لا يحدث تحديث لاحق أثناء كتابة البلاغ. لا يخزن عامل الخدمة طلبات ولا يعترض اتصال خادم النظام الخارجي. إذا حُظر التسجيل أو لم يُفعّل العزل، يستمر التشغيل بخيط واحد. في اختبار المتصفح السحابي بخيط واحد استغرق أول تصنيف 528.2 ثانية؛ لذلك لا تُفترض سرعة مناسبة لجميع الأجهزة. الحد الزمني 15 دقيقة للتنزيل ولكل من مهمتي التصنيف واختيار المرجع، مع إمكانية الإلغاء الفوري.

يعمل النموذج نفسه في صفحتي الصيانة وتقارير الأعطال عبر العامل المخصص. تُسجّل هويته وإصداره وضغطه ومحركه ومدة التنفيذ مع نتيجة البلاغ. تتحقق الواجهة الخلفية من تطابق الإصدار وبصمة نص البلاغ. النتيجة مصرح بها من العميل وليست إثباتًا مشفرًا لتنفيذ النموذج.

## التقييم وإعادة القياس

جدول ONNX السابق: 13/40 للنموذج 0.6B مقابل 32/40 للنموذج 1.7B؛ Accuracy 32.50% مقابل 80.00%، وMacro‑F1 25.44% مقابل 77.98%. هذه نتائج مجموعة تطوير استُخدمت أثناء تحسين التوجيه، وليست اختبارًا مستقلًا ولا قياسًا للدقة السريرية أو نجاح الإصلاح الفعلي.

يُعيد الاختبار الحالي تشغيل الحالات الأربعين الثابتة وست حالات لاختيار المرجع في Chromium مع WASM، ويختبر أيضًا صفحة التشغيل الفعلية عبر العامل المستخدم في البلاغات. تسجل النتائج الفردية ومقاييس Accuracy وMacro‑Precision وMacro‑Recall وMacro‑F1 وبصمات البيانات والإعدادات وإصدار المتصفح والتاريخ في مرفق GitHub Actions المسمى `qwen17-browser-evaluation`. تُؤخذ أرقام النسخة الحالية من هذا المرفق بعد اكتمال التشغيل، ولا تُستبدل بأرقام الجدول السابق.

```bash
cd frontend
npm ci
npm run build
npx playwright install chromium
npm run benchmark:llm
```

تُعرض الحالات والنتائج أيضًا في `/model-upgrade-test.html`. يتطلب اجتياز اختبار المرجع نجاح الحالات الست، والتصنيف تحسنًا على خط الأساس المثبت 13/40. لا يمثل هذا الشرط إثباتًا بنسبة تطابق مع عنوان البحث. يبقى قياس جودة الحلول الفعلية بحاجة إلى بيانات بلاغات مستقلة ونتائج تحقق المختصين.

## نتيجة GGUF المقاسة

أكمل النموذج الحالات الأربعين بخيط واحد ثم بأربعة خيوط، وحقق في التشغيلين 36/40 (90%). بلغ Macro‑Precision ‏91.85%، وMacro‑Recall ‏90.00%، وMacro‑F1 ‏88.92%. تحفظ النتائج الفردية في `docs/evaluation/qwen17-gguf-four-thread-20260924.json` مع بصمات البيانات والإعدادات. مصدر التشغيل المتوازي هو سجل GitHub Actions رقم 36033150348؛ اكتمل التصنيف قبل إلغاء التشغيل أثناء اختبار المراجع، ولذلك لا يدل هذا السجل على اجتياز اختبار المراجع كاملًا.

استغرق تحميل النموذج 60.2 ثانية وأول تصنيف 256.1 ثانية في تشغيل Windows Chromium بأربعة خيوط. لا تصلح المقارنة مع الجهاز السحابي ذي الخيط الواحد لاستنتاج تسارع مضبوط لاختلاف الجهازين. ظهرت أربعة أخطاء، ثلاثة منها في POWER، واستدعاء هذه الفئة 40% فقط. لذلك تبقى مراجعة المختص ضرورية، ولا تعني الدقة الإجمالية نجاح إصلاح الأعطال أو دقة سريرية أو نسبة تطابق الرسالة.

اختبار CI التالي يركز على الحالات المرجعية الست ومسار العامل الفعلي تحت حصة تخزين منخفضة، باستخدام `npm run benchmark:llm -- --skip-classification --low-storage`. يبقى الأمر الافتراضي أعلاه متاحًا لإعادة التقييم الكامل. مجموعة الأربعين مجموعة تطوير استُخدمت أثناء ضبط التوجيه؛ يلزم اختبار مستقل أكبر لتقدير التعميم.
